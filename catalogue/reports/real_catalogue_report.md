## Method and politeness

1. `seed_v2.csv` (see `seed_v2_CHANGELOG.md`) -> `real_import_input.csv`: the five rule columns are left out, because the importer would store them as confirmed rules (`confirmed_by=catalogue_import`), against D6.
2. `POST /api/v1/catalogue/imports` on our own stack (real mode, `SIMULATION_MODE=false`). The worker's importer checks robots.txt on every hop, waits at least 1 s between two requests to the same site, follows redirects by hand through the SSRF guard, reads member counts from the platform API, detects the page language and scores relevance with the lexicon (no LLM).
3. Preflight (this script, the importer's `Fetcher`): every rules page GET with robots.txt on every hop, 1 request/s/site, sha256 of the bytes received (capped at 256 KiB). robots.txt is also evaluated for the user agents the capture job sends (`IncuBrixRulesReader/1.0` and the default `python-httpx`), and for the platform API URL it reads. A row is captured only when everything is allowed and the page answered 200.
4. `POST /api/v1/destinations/{id}/rules/capture` with the preflight's final URL (so the capture needs no redirect), `LLM_PROVIDER=mock`. The worker checks robots.txt again, waits 1 s per host, verifies every quote verbatim and stores a `proposed` rule set. No proposal was confirmed or rejected. Phases ran one after another, so no two phases hit one host at the same time.
