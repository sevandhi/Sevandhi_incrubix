## What changed and why

1. **Slack rows -> `assisted` (decision D8).** These are third-party workspaces. Our Slack app is not installed there, so a person posts from an assist pack. `connector_key=assisted`, `surface=community` (maps to the assisted `post` surface), `automation_allowed=no`. Their level ceiling is L1. `platform_key` stays `slack`.
2. **MRSS rows get our own feed key.** We publish a Media RSS feed and the site consumes it. Each row gets its own `instance_feed_key` (served at `/api/v1/feeds/<key>/mrss.xml`). The site only starts reading it after a person submits the feed URL there.
3. **Free-text rule summaries.** The rules engine reads only structured values (`frequency_cap` as `N/<ISO-8601>`, `self_promo_allowed` yes/no/ratio(n), `link_policy` any/none/no_shorteners/allowlist, and yes/no flags).
   - Values that already parse are unchanged.
   - Three values are re-expressed because the row's verified quote supports them (listed below).
   - `disclosure_required=prohibited` means AI-generated content is banned. That is not a disclosure rule, so the field is blank and the new column `ai_content_banned=yes` keeps the fact (negative rules cases, D8).
   - Everything else (`restricted`, topical link guidance, launch-frequency prose) has no structured equivalent. The field is blank and the original text is kept in `rules_text`. These rules stay unconfirmed until a person confirms a rules proposal.
4. **New columns:** `instance_feed_key`, `ai_content_banned`, `rules_text`, `level_ceiling` (the highest level the connector tier can reach after a certification; real rows are not certified, so their level is L0), `v2_changes` (this row's changes).

**Do not import seed_v2 with its rule columns as they are.** The importer stores a row's rule columns as a confirmed rule set (`confirmed_by=catalogue_import`). Decision D6 says only a person confirms real-catalogue rules, so `scripts/p5c_catalogue.py import-csv` leaves the five rule columns out of the import file. The rules then come from rules capture as proposals (`confirmed_by=pending-human`).
